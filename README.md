# Ajay B J — Portfolio

Personal portfolio for **Ajay B J**: fintech & business operations, data analytics and AI-assisted product building.
Built with **Next.js 15 (static export) · TypeScript · Tailwind CSS v4**, deployed on **Netlify**.

> Read `UPGRADE_REPORT.md` for the inspection of the old site, the design decisions and the test results.

---

## 1. Project structure

```
src/
  content/              ← ALL text lives here. Edit these, not the components.
    site.ts             name, headline, contact details, links, SEO text
    experience.ts       work history
    skills.ts           skill groups + evidence levels
    projects.ts         projects & full case studies (+ earlier work)
    journey.ts          learning-journey timeline, "currently learning"
    types.ts            TypeScript types for all of the above
  app/
    layout.tsx          <head>, SEO metadata, JSON-LD, theme script, header/footer
    page.tsx            home page (all 10 sections)
    projects/[slug]/    case-study page template (one page per project with `sections`)
    not-found.tsx       404 page
    robots.ts, sitemap.ts   generated at build time
    globals.css         design tokens (colours, fonts) + base styles
  components/
    ui.tsx              buttons, badges, section headings, tags
    layout.tsx          header, footer, project card, flow diagram
    client.tsx          interactive bits: theme toggle, mobile menu, filter, gallery, contact form, copy button, back-to-top
    Icon.tsx            inline SVG icons
public/
  images/               screenshots + profile photo (WebP)
  fonts/                self-hosted Inter + JetBrains Mono (Latin subset)
  data-projects.html    Data & Automation Lab page (built from the data-portfolio repo)
  assets/               images used by data-projects.html
  Ajay-B-J-Resume.pdf   your current resume (replace this file to update the download)
  og.png                social-preview image, generated by `npm run assets`
  __forms.html          Netlify Forms registration skeleton (do not delete)
  favicon.svg
scripts/build-assets.ts generates og.png (and, optionally, a one-page resume) from src/content
netlify.toml            build command, publish folder, headers
```

## 2. Install & run

Requires Node.js 20+ (22 recommended).

```bash
npm install
npm run dev          # http://localhost:3000, live reload
npm run build        # static site → ./out
npx serve out        # preview the production build locally
npm run assets       # regenerate og.png (needs: npx playwright install chromium)
npm run lint
```

## 3. Deploy to Netlify

The current live site (explorexplorer.netlify.app) is a drag-and-drop upload with no Git connection. **Nothing in this repo changes it until you deploy.**

### Recommended: connect a GitHub repo (automatic deploys + previews)
1. Create a GitHub repo (e.g. `portfolio`) and push this folder.
2. In Netlify → *explorexplorer* → **Project configuration → Build & deploy → Link repository**.
3. Settings are read from `netlify.toml`: build command `npm run build`, publish directory `out`, Node 22. No environment variables are needed.
4. Netlify builds every push. Pull requests get a **Deploy Preview** URL to check before merging.

### Quick: CLI without Git
```bash
npm run build
npx netlify-cli login
npx netlify-cli link            # choose the existing "explorexplorer" project
npx netlify-cli deploy --dir out          # DRAFT deploy → gives a preview URL, live site untouched
npx netlify-cli deploy --dir out --prod   # only when you're happy: replaces the live site
```
`.netlify/` is in `.gitignore`. Never commit it.

### Turn on the contact form (one time, free)
Netlify → *explorexplorer* → **Forms → Enable form detection**, then redeploy.
Submissions appear under Forms. Add an email notification under **Forms → Submission notifications**.
The free plan includes 100 form submissions per month, which is plenty for a portfolio; there is no cost unless you upgrade.
Spam is filtered by Akismet plus a honeypot field. If a real message seems missing, check the **Spam** tab first.

### Undoing a bad deploy
Netlify keeps every deploy. If a published version has a problem, the safest fix is to correct the content and deploy again.
If you need the previous version back immediately, open **Deploys**, choose the last good deploy and select **Publish deploy**.
Your current June 2026 site stays in the deploy list (deploy `6a2a44a6…`), so you can always go back to it.

## 4. Editing content

| I want to… | Edit |
|---|---|
| Change name, headline, email, phone, LinkedIn, GitHub | `src/content/site.ts` |
| Hide the phone number | set `phone: ""` in `site.ts` |
| Add education details | `site.education` in `site.ts` |
| Update a job / add a new job | `src/content/experience.ts` (newest first) |
| Add or re-label a skill | `src/content/skills.ts`, set `level` to `professional`, `applied`, `working` or `learning` |
| Add a project | copy an object in `src/content/projects.ts` (see below) |
| Change project status | `status` in `projects.ts`: `live-demo`, `live`, `experiment`, `in-progress`, `planned`, `completed` |
| Update the timeline | `src/content/journey.ts` |
| Change colours | CSS variables at the top of `src/app/globals.css` (dark = `:root`, light = `[data-theme="light"]`) |

After editing, build and deploy. Remember to update your resume PDF if the same facts changed.

### Add a project
```ts
{
  slug: "my-new-project",                 // becomes /projects/my-new-project
  title: "My New Project",
  tagline: "One-line description",
  status: "in-progress",
  statusNote: "Prototype working",
  categories: ["Data & Analytics"],       // drives the filter buttons
  summary: "1–2 sentences for the card.",
  role: "What I did.",
  aiAssisted: "How AI was used (optional but recommended).",
  tools: ["SQL", "Power BI"],
  cover: { src: "/images/my-shot.webp", alt: "Describe the image", width: 1280, height: 720 },
  gallery: [ /* more screenshots, same shape */ ],
  links: [{ label: "Live site", href: "https://…" }],
  sections: [{ heading: "The problem", body: "…" }, { heading: "What I built", bullets: ["…"] }],
}
```
No `sections` → card only. With `sections` → a case-study page is generated automatically and added to the sitemap.
To link a card to another page instead (like the Data Lab), set `externalPage: "/some-page.html"`.

### Replace screenshots
1. Take a screenshot (about 1280–1600 px wide).
2. Convert to WebP (e.g. squoosh.app, quality about 80) and put it in `public/images/`.
3. Update `src`, `width` and `height` in `projects.ts`. Width and height prevent layout jumps.

### Update the resume
Replace `public/Ajay-B-J-Resume.pdf` with your new PDF (keep the file name, or change `resumePdf` in `site.ts`), then rebuild.
When your resume changes, update `src/content/experience.ts` and `skills.ts` too, so the site and the PDF say the same thing.
(Optional: `npm run assets -- --resume` generates a one-page resume from the site content, which overwrites the PDF.)

### Update the Data & Automation Lab page
It's built in the separate `ajay-data-portfolio` repo: `python portfolio-section/build_section.py`, then copy
`portfolio-section/dist/data-projects.html` and `dist/assets/` into `public/`.

## 5. Troubleshooting

| Problem | Fix |
|---|---|
| Contact form says "Couldn't send" | Form detection isn't enabled in Netlify, or you're testing locally (forms only work on Netlify). Enable it and redeploy. |
| Form submissions missing | Check Forms → **Spam**. Test with a real-looking message, not "test". |
| `/projects/x` shows 404 after adding a project | The project needs a `sections` array, and the slug must be unique. Rebuild. |
| Build fails with a type error | The message names the file and line. Usually a missing field in `projects.ts`. |
| Images look stretched | The `width`/`height` in `projects.ts` must match the real image size. |
| Theme stuck in light/dark | Clear the `theme` key in browser localStorage. |
| `npm run assets` fails | Run `npx playwright install chromium` once. |
| Old links like `/#hero` | The home page still loads; unknown anchors simply land at the top. |

## 6. Honesty rules this site follows
- No invented employers, certifications, metrics, traffic or sales.
- Every project shows its real status. Demo data is labelled as demo data.
- AI-assisted work is described as AI-assisted.
- Skills are labelled by evidence, not by percentage bars.
